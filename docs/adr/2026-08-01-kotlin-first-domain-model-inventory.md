# Kotlin-First Domain Model Inventory (Phase 0)

## Status

Companion to [2026-08-01-kotlin-first-domain-model-and-navigation.md](./2026-08-01-kotlin-first-domain-model-and-navigation.md). Produces the checked-in inventory required by ADR section 8 and satisfies the Phase 0 exit criteria of that ADR.

## Scope note

This inventory covers every production Kotlin class under:

```text
app/src/main/java/com/mxt.anitrend/model/entity/**
```

95 classes were enumerated from source and each is assigned exactly one planned target role. Test sources, generated ObjectBox metadata (`NotificationHistory_`, `MyObjectBox`), and classes outside `model.entity` are out of scope. The inventory records the state of the tree at the time of writing; it must be updated by every migration PR per ADR section 10.

## Methodology

Evidence was collected directly from source with the following searches, not inferred from class names:

- File and declaration enumeration: `find ... model/entity -name '*.kt'` and a top-level `class|interface|enum class|object` scan (one declaration per file for all 95 files).
- ObjectBox: `@Entity`, `@Id`, `@Index`, `@Convert` annotations plus `DatabaseHelper`/`BoxQuery` box registrations.
- Parcelable: `Parcelable.Creator`, `writeToParcel`, `describeContents`, `@Parcelize`, `@IgnoredOnParcel`.
- Serializable: `Serializable` markers, `com.google.gson.annotations.SerializedName`, `org.simpleframework.xml.*`, generated GraphQL imports (`co.anitrend.retrofit.graphql.*`, `com.mxt.anitrend.graphql.generated.*`).
- RecyclerView dependency: `: RecyclerItem`, `: RecyclerHeaderItem` inheritance.
- Mutable fields and model behaviour: `var` field scan and `fun toggle|merge|increment|clone|set|apply|parse|calculate` scan.
- Consumers: `import com.mxt.anitrend.model.entity.<Class>` resolved across `app/src/main/java` excluding the entity package itself.
- Navigation consumers: `putParcelable`, `getParcelable`, `putExtra`, `IntentBundleUtil.checkIntentData`, `KeyUtil.arg_id` usage sites.

## Role legend

Planned target role values map to the ADR section 1 classification:

| Value | ADR role | Meaning |
|---|---|---|
| 1 Domain | Domain model | Immutable, pure-Kotlin application value |
| 2 Local entity | Persistence entity | ObjectBox-backed, data-layer local state |
| 3 Remote DTO | Remote transport model | API/transport response shape |
| 4 UI model | Presentation or RecyclerView model | Screen or adapter rendering shape |
| 5 Screen param | Navigation parameter | Typed `ScreenParam` bundle argument |
| 6 Framework/container | Framework or container type | Generic transport/grouping plumbing |
| 7 Obsolete | Obsolete compatibility type | No longer needed after migration |

## High-risk follow-ups

- `MediaBase` is the widest blast radius: 55 import sites outside the entity package, a handwritten Parcelable, `RecyclerItem` inheritance, `toggleFavourite()`, and a full-entity fragment argument in `BottomSheetSeriesManage`. It must be split into aggregate-specific records, not one oversized `MediaRecord`.
- `UserBase` and `User` combine ObjectBox persistence, `@Parcelize`, converter-backed fields, and mutation (`toggleFollow()`). The follow-state mutation path must move to `ToggleUserFollowInteractor` + `UserStore` before the parcel contract is touched.
- `MediaList.clone()` returns `this`, so any caller believes it isolated a copy. Callers must be enumerated before the method is removed.
- Cross-type equality in `FeedReply`/`FeedList` (and `MediaList` vs `MediaBase`) is relied on by diffing and sets. Converting these to data classes silently changes equality to full structural comparison; each aggregate needs explicit equality tests.
- Handwritten Parcelable state lives in class bodies (`MediaBase`, `MediaList`, `User`, `MediaListCollection`, `MediaCharacter`, `Notification`, `Thread`, `Review`). Migration must move every parcelled property into the primary constructor before deleting the handwritten code.
- `Genre` and `MediaTag` mix persisted state with UI selection (`isSelected`). The UI state must be split from the ObjectBox entity before either moves.
- ObjectBox converter-backed fields (`UserBase.avatar` via `ImageBaseConverter`, `User.options`/`mediaListOptions`) couple remote DTO shapes to the persistence schema. Converter compatibility must be preserved until the entity migration lands.
- Generated GraphQL enum/input types are already exposed in domain commands, stores, and ViewModels (`MediaListStatus`, `MediaType`, `FuzzyDateInput`, `ScoreFormat`, `LikeableType`, `ReviewRating`, `ReviewSort`, `ActivityType`, `MediaListSort`). These are existing, scoped exceptions and must be allowlisted in architecture baselines, not treated as domain violations.
- `MaterialSearchView.SavedState` (a handwritten `Parcelable.Creator` inside a custom view) is a view-state exception, not a domain model; it must be scoped out of any "no handwritten Parcelable" architecture rule.
- `StatsRing` imports `android.graphics.RectF` and is a widget data holder; it must be pushed to presentation so the domain layer stays Android-free.
- `AniListContainer` exposes the generated `GraphError` type at the retrofit boundary. That boundary exposure is acceptable as a scoped exception; the type must not cross into ViewModel state.
- `NotificationHistory_` and `MyObjectBox` are generated ObjectBox metadata classes that are consumed outside the entity package; they are excluded from this inventory but will move with the local entity relocation.

They remain consumed (by `User` converters and the `UserStats` aggregate), so they keep their assigned target roles, but each should be re-checked for earlier removal during its aggregate migration.

Metadata classes such as `ScoreDistribution`, `FormatStats`, and `GenreStats` show no class-body `var`; primary-constructor `var` parameters were not exhaustively distinguished from `val` for every class and should be confirmed per aggregate during migration.
