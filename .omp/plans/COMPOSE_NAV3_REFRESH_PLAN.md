# Compose & Navigation 3 Refresh Plan

## Context
Extend AniTrend/anitrend-app PR #1154 in the existing `feat/compose-migration-foundation` workspace, without creating or switching worktrees. Replace query-variant destinations with preset-driven screens, including one Library view for My Anime List, My Manga List, and Airing; adopt Compose Material 3, Navigation 3, API 24 minimum support, bottom action bars and a simple bottom-sheet route drawer. Complete all Activity/Fragment/sheet and RecyclerView migrations, retaining only a narrowly scoped Markwon rendering bridge, and redesign settings, social conversations, media/people details, onboarding and changelog under a binding Compose-first `DESIGN.md`.

**Observed workspace:** current branch is `feat/compose-migration-foundation`; `app/src/debug/res/layout/` contains untracked user work and must be preserved. Unless qualified otherwise, Kotlin paths below are rooted at `app/src/main/java/com/mxt/anitrend/`; paths explicitly marked new are proposed additions. Existing code remains the source for behavior not deliberately changed here.

## Approach

1. Replace the XML-specific rules in `DESIGN.md` with the following binding Compose-first rules, not a contradictory addendum. Port the product intent and decision order from `../anitrend-v2/DESIGN.md`: comprehension, task efficiency, consistency, then expression. Preserve AniTrend's dense identity/artwork/progress hierarchy and existing light/dark/black preferences; avoid copying v2's gradients, all-equal chip walls, unfinished features or layered account-switcher animation.
2. Keep and evolve `ui/designsystem/AniTrendTheme.kt`, not a competing `Theme3`. Retain condensed typography; use headlineSmall for screen headings, titleMedium for sections, bodyMedium for content and labelLarge for controls. Use `Shapes(extraSmall=4.dp, small=8.dp, medium=16.dp, large=24.dp, extraLarge=28.dp)` with RoundedCornerShape values; chips/buttons use full-rounded component shapes, posters medium, groups large and sheets extraLarge. Keep 16dp screen/card insets, 8/12dp intra-group gaps and 24dp between major sections. Use tonal layering, not ornamental shadows or nested cards around every row. No hard-coded palette, per-screen theme or invented extraLargeIncreased Shapes property.

Each destination supplies its bottom actions; a scrollable heading or artwork hero supplies top identity, never a second toolbar. Bottom bars remain visible while scrolling. One bar per screen: leading Menu at roots or Back below roots; at most three other frequent actions, with rare actions in localized overflow. These are action bars, not icon-only primary-destination navigation bars. Never move row-specific Like/Reply into a global bar, duplicate an action at top and bottom, or stack a FAB over a composer.

Reuse v2's rounded sheet/tonal grouping only; no sandwich animation, dynamic routing engine or account switcher. Back/scrim/drag dismiss the drawer without navigating. No TabLayout, TabRow, pager-backed tab strip, raw ordinal or enum `.name`/capitalization as UI copy. Use existing localized resources first, add missing `label_<context>_<value>` resources and the shared `label_unknown` resource; null/unknown metadata is omitted where optional or displayed as localized Unknown where a row requires a value, never as an invented selectable query option.

Replace display uses of `CompatUtil.capitalizeWords` in `MediaOverviewViewModel`, `SeriesYearTypeTextView`, `AiringTextView`, `RecyclerHeaderItem`/`GroupingUtil`, `CharacterMediaHeaderRow`, and `MediaListFragment` status choices as those consumers move to Compose; do not change wire `.name` serialization in repositories/stores.
